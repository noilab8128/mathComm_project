- AI 검사는 이제 실행 한 번에 코드 실행 환경을 하나만 써서 비용이 크게 줄었습니다.

## 7. 검사 설명: Automatic check와 AI check

두 검사는 같은 문제를 서로 다른 방식으로 확인합니다. Automatic check는 프로그램이 정해진 규칙으로 보고, AI check는 AI가 문제를 직접 풀어 봅니다.

| | Automatic check (L0, L1) | AI check (L2, L4) |
|---|---|---|
| 하는 일 | 문제와 정답이 **정해진 규칙**에 맞는지 프로그램이 확인 | AI가 **정답을 모르는 상태로 직접 풀어 보고** 그 답을 DB 정답과 비교 |
| 실행 프로그램 | `scripts/verify/report.py` (AI 사용 안 함) | `scripts/verify/ai_check.py` (OpenAI `gpt-6.2-sol` + 코드 실행 환경) |
| 실행 시각 | 매일 03:00 + 리뷰 화면의 Run automatic check 버튼 | 매일 03:40. 직접 실행은 GitHub Actions에서 |
| 대상 | **매번 243개 전부** | **아직 AI 검사 결과가 없는 문제만** (새 문제, 내용이 바뀐 문제). 한 번에 최대 30개 |
| 비용 | 없음 | 있음 (OpenAI, 월 한도 $9) |
| 결과의 무게 | 경고 또는 **실패**가 될 수 있음 | **경고만** (AI도 틀릴 수 있어서 문제를 숨기지 않음) |

**검사 단계 (L0, L1 …)**

| 단계 | 이름 | 하는 일 | 상태 |
|---|---|---|---|
| L0 | 형식 검사 | 풀이 첫 줄의 `Answer: 숫자`를 정답 확인과 같은 방식으로 읽을 수 있는지, 제목·본문·풀이가 비었는지, 난이도 범위, 대회 라벨과 난이도가 맞는지, 금지 표현("It is known that", 다른 단계 답 참조), 답 안내 문장 중복, 세부 카테고리 누락, 사다리 연결 끊김, Challenge 정답이 단계 정답에 나오는지 | 운영 중 |
| L1 | 원본 대조 | v2 사다리만: DB 정답이 markdown 원본 정답과 같은지, 사다리별 검증 스크립트 9개가 통과하는지 | 운영 중 |
| L2 | 독립 재계산 | AI에게 문제 본문만 주고, AI가 코드를 짜서 푼 답을 DB 정답과 비교. 다르면 경고 | 운영 중 |
| L3 | AI 여러 번 풀기 | 정답 없이 여러 번 풀게 해서 답이 일치하는지 | 계획만 있음 |
| L4 | 애매함 | 문제를 다르게 읽을 수 있는지, 해석에 따라 답이 달라지면 경고. L2와 같은 요청에서 함께 확인 | 운영 중 |
| L5 | 규칙 평가 | `LADDER_RULES_v2`, `LEVEL_GUIDE` 기준으로 AI가 평가 | 계획만 있음 |
| L6 | 원본 유사도 | 참고한 원문과 너무 비슷한지(저작권) | 계획만 있음 |
| L8 | 공개 후 관찰 | 학생 풀이 기록: 오답이 한 값에 몰리는지, 정답률이 이상한지 | 계획만 있음 |

L7은 쓰지 않는 번호입니다.

**결과 등급과 영향**

| 등급 | 의미 | 영향 |
|---|---|---|
| pass | 문제 없음 | 없음 |
| warn (경고) | 사람이 한번 봐야 함 | 리뷰 목록에 Warning으로 표시, 일괄 승인 대상에서 빠짐. 학생 화면은 그대로 |
| fail (실패) | 규칙 위반이 확실함 (L0만 해당) | 승인할 때 "실패 내용 확인" 체크와 코멘트 필요. 승인 뒤 내용이 바뀌었는데 실패하면 학생에게 숨겨짐 |
| info (참고) | 기록만 남김 | 없음 |

- 문제 하나의 전체 상태(리뷰 목록의 Passed / Warning / Failed)는 L0·L1·L2·L4 중 **가장 나쁜 결과**로 정해집니다.
- AI 결과(L2·L4)는 문제 내용이 바뀌기 전까지 유지되어, 매일 밤 Automatic check가 다시 돌아도 사라지지 않습니다.
- **이력 화면**(`/admin/reviews/history`): Runs는 GitHub에서 실행된 기록 전부입니다(Nightly는 밤 자동 실행, Manual / button은 직접 실행). Saved results는 실행마다 DB에 남긴 결과입니다. Automatic check는 내용이나 결과가 바뀐 문제만 저장하므로, 변화가 없던 날은 Runs에만 나옵니다.
